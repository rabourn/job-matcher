# Setting up the job alert pipeline

One-time setup for the screen-alerts pipeline (PRD: PRD-job-alert-pipeline.md).

## Prerequisites (all in place as of 2026-06-11)

- `data/pipeline.local.json`: copied from `pipeline.example.json`, paths filled in
- `data/career-brief.local.md`: local copy of the Google Doc career brief
- `data/master-cv.idml`: the master CV (save over this file to update it)
- `data/story-map.json`: generated by `scripts/idml-story-map.py`; regenerates
  automatically when the CV's mtime changes
- `data/ledger.db`: created by `scripts/ledger.py init`
- Gmail access: the claude.ai Gmail connector, validated to work in headless
  `claude -p` runs
- Vault: `~/cairn/projects/job-search/` with `reports/` and `apply-queue.md`

## Test a run manually

```bash
bin/run-pipeline.sh            # full headless run, logs to logs/run-*.log
PIPELINE_MODEL=sonnet bin/run-pipeline.sh   # cheaper model override
```

Or interactively in a Claude Code session from the repo root: "run the
screen-alerts skill" and watch it work.

## Install the schedule (Monday and Thursday, 07:00)

```bash
cp setup/com.rabourn.job-alerts.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.rabourn.job-alerts.plist
```

To trigger once immediately for testing:

```bash
launchctl start com.rabourn.job-alerts
```

To change the schedule, edit the plist's `StartCalendarInterval` entries,
then `launchctl unload` and `load` again. Note launchd weekdays: 0 = Sunday.

If the run needs Dropbox or other protected paths later, grant Full Disk
Access to `/bin/bash` (System Settings > Privacy & Security), same caveat as
recall's sync job.

## Where things land after each run

- Report: `reports/YYYY-MM-DD-job-screen.md` and `~/cairn/projects/job-search/reports/`
- Apply queue: `~/cairn/projects/job-search/apply-queue.md`
- CV drafts: `data/cv-drafts/CV-rabourn-<company>-<date>.idml` plus `.changes.txt`
- Run history: `runs` table in `data/ledger.db`; one line per run in `logs/pipeline.log`

## Maintenance

- Update the career brief: re-fetch the Google Doc into
  `data/career-brief.local.md` (the pipeline warns when the local copy is
  older than 60 days).
- Update the CV: save the new export over `data/master-cv.idml`. The next run
  regenerates the story map and flags it in the report for a quick check.
- Mark a role applied or skipped: tick the checkbox in `apply-queue.md`, or
  tell Claude in any session ("mark the Verdant role applied"); the ledger is
  the source of truth.
- Future source ideas: a Workday scanner would lift ATS resolution
  substantially (Mastercard, Danske Bank, Accenture, and BBH all resolve to
  Workday today and come back unverified). Indeed/Google alert emails can be
  added via `gmail_senders` once a parser variant exists.
